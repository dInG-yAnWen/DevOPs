## 2. E4运行入口与额外设置

在课程Ubuntu服务器上使用全新学号目录执行：

```sh
mkdir -p /root/<学号>
cd /root/<学号>
git clone https://github.com/oVLVo11/DevOps_A14.git buildchecker
cd buildchecker
git config --local user.name <学号>
git config --local user.email <学号>@localhost
git checkout --detach 0a23b30d5c1e6eef118ce8d422c4a5b0444215f5
git rev-parse HEAD
make all
```

普通成员只重跑、不commit和push，因此课程手册允许使用`<学号>@localhost`。不得在共享服务器设置全局Git身份，不需要填写真实API Key；`.env`由`.env.example`自动生成并设为权限600。

`make all`依次执行：

1. `make doctor`：生成`env.json`；
2. `make build`：生成`build.log`、`image.json`、`toolchain.lock`；
3. `make test`：生成`test.log`，预期`3 passed`；
4. `make smoke`：生成`smoke.json`，预期`passed=true`、程序输出1、跟踪到`config.h`且不读取`unused.h`；
5. `make scan`：生成`secret-scan.txt`，检查工作区、Git历史和镜像。

每次运行生成独立的`work/<时间>/`目录。

### 相对课程A组模板的修改

A14以课程`E4实验包/A-buildchecker`为基线整合到现有仓库，不引入B组DRAFT实现或`docker.sock`挂载。为适配课程ECS，只有两项必要运行修复：

1. 容器内访问`deb.debian.org`连续两次停滞，因此Debian主源和安全源切换为`https://mirrors.aliyun.com`；apt仍执行签名校验，固定基础镜像OCI digest未改变。
2. 镜像内直接调用`pytest`控制台入口不能导入`/app/buildchecker`，因此`make test`改为`python3 -m pytest`；pytest版本和测试内容未改变。

两次真实失败日志保存在`e4/evidence/20261008-a14-e4/troubleshooting/`，没有删改成成功记录。
