# A14 对 B14 的 E2 接口确认回复

日期：2026-09-25  
A14 仓库：`https://github.com/oVLVo11/DevOps_A14.git`  
B14 仓库：`https://github.com/dInG-yAnWen/DevOPs.git`

## 一、接口方案

是否接受 B14 提出的接口方案：**接受 E2 schema_version 1.0**。

A14 接受：

- `POST /v1/dockerfile-jobs` 创建 DRAFT Job；
- `GET /v1/jobs/{job_id}` 查询 Job；
- 异步受理使用 HTTP 202；
- `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`TIMED_OUT`、`CANCELLED` 六种状态；
- DRAFT 默认最多尝试 3 次、默认总超时 1800 秒；
- `artifact://` 作为逻辑产物 URI；
- DRAFT 成功要求 Dockerfile/镜像元数据可读取、build 与 verify 退出码均为 0、产物带 `producer_job_id`；
- 正常检测到 MISSING 或 REDUNDANT 属于成功分析结果，FULL_CHECK/INCREMENTAL_CHECK 可返回 `SUCCEEDED`；
- `GOAL_UNMET`、`SYSTEM`、`INPUT`、`CONTROL` 用于区分目标未达成、系统异常、输入错误和取消。

E2 不增加 `baseline.build_commands_uri` 字段，以维持双方 1.0 Schema 一致。EChecker 所需的历史构建命令快照暂由 A14 在服务内部按 `repository_url + base_commit + configuration_id` 保存；是否在后续版本公开该字段列入 E3 Backlog。

## 二、A14 项目资料

- A14 服务：BuildChecker（FULL_CHECK）、EChecker（INCREMENTAL_CHECK）。
- E2 项目仓库：`https://github.com/oVLVo11/DevOps_A14.git`。
- E2 契约样例使用人工仓库 URL、C0/C1 提交、`make clean && make` 和 `make test`，不代表真实项目。
- 真实实验仓库、完整 SHA、构建命令、验证命令、工具链和基础镜像：**E3 共同选定后补充**。
- E2 网络访问：`DISABLED`，校验可离线执行。
- E2 不要求运行真实镜像、端口或测试数据。

## 三、产物读取方式

- E2 使用 `contracts/artifact-manifest.json` 将完整 `artifact://` URI 映射到 `contracts/artifacts/` 内文件。
- 读取时必须检查 URI 精确匹配、路径不越界、文件存在、SHA-256 一致、生产 Job/仓库/commit/configuration 一致。
- A14 消费 DRAFT 环境字段：`image_ref`、`configuration_id`、`dockerfile_uri`、`producer_job_id`。
- A14 同时读取 build/verify 日志用于诊断，但日志不是成功结果的替代品。
- FULL_CHECK 产生 `ACTUAL_GRAPH`、`DECLARED_GRAPH`、`ERROR_REPORT`。
- INCREMENTAL_CHECK 产生更新后的三类产物和 `findings_delta`。
- A14 向 MDFixer 发布非空、MD-only 的 `ERROR_REPORT`，保留原 `finding_id` 和生产来源。

## 四、联调确认

- E2：A14 可以通过随仓库提供的 manifest 和校验器读取 B14 人工产物样例。
- E3：真实 registry、对象存储、镜像拉取权限和跨组读取证据尚未建立。
- 当前 B14 远程 HEAD 仅含 README；完整契约来自 B14 提供的压缩包。请 B14 正式发布后补充真实契约提交 SHA，A14 再固定引用版本。

## 五、A14 对 B14 的交付

A14 在 E2 提供 FULL_CHECK、INCREMENTAL_CHECK 请求/受理/结果样例，actual/declared graph、完整 findings、MD-only findings 产物，以及统一校验器可复现结果。E3 再提供真实检测报告和对 MDFixer 候选 patch 的重检结果。
