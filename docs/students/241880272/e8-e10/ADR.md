# 决策记录

背景与约束：

E8 的补丁生成依赖报告中的缺失依赖结论。原 `patch()` 只用 Git `HEAD` 判断报告是否失效。若工作区内容改变但未提交，例如把 `main.c` 中对 `config.h` 的引用替换成等效常量定义，GCC 已不再依赖该头文件，但 `HEAD` 不变，旧报告仍会被接受并生成错误补丁。约束是不能改变既有实验流程、不能依赖网络、不能修改样例输入来绕过检查。

选择与替代方案：

- 选择：在 `scan()` 生成的报告中记录实际扫描输入（`.c`、`.h`、`Makefile`）的 SHA-256，并在 `patch()` 生成补丁前重新计算比较；不一致即 `STALE_REPORT`。
- 替代 A：在 `patch()` 时重新执行一次 `scan()` 并比较 `findings`。更全面，但会额外调用 GCC，且需要区分“报告旧”与“输入本身不可扫描”。
- 替代 B：要求工作区干净（`git status` 为空）。约束过强，会阻止手工实验中的合法中间状态，也不能覆盖已暂存但未提交的变化。

代价与覆盖范围：

- 每次扫描多一次文件读取与哈希，成本可忽略。
- 指纹只覆盖项目内 `.c`、`.h` 与 `Makefile`，不覆盖环境变量、宿主编译器版本或项目外配置；这些仍由既有 `key`（指令、配方、flags、编译器）与运行环境共同约束。
- 旧版报告没有 `input_sha256` 字段，会被视为失效并拒绝；这是有意的严格化。
