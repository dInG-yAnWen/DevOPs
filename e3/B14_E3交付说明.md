## 4. MDFixer 样本（缺失 `config.h`）

目录：[`fixtures/mdfixer/`](fixtures/mdfixer/README.md)。

### 4.1 为什么这是 MD（缺失依赖）

| 事实 | 证据 |
| --- | --- |
| `main.c` 实际读取 `config.h` | 源码第 8 行 `#include "config.h"`，编译 `main.o` 时必须读取 |
| `Makefile.before` 未声明该边 | 第 7 行 `main.o: main.c`，无 `config.h` |
| 后果：复用旧产物 | 只改 `config.h` 后普通 `make` 不重编译，程序输出旧值 |
| 对照：clean 重建正确 | `make clean && make` 后输出新值 |

即“Makefile 声明的依赖”小于“编译期实际读取的依赖”，属于缺失依赖（MD），不是编译错误，
也不是冗余声明（RD）。声明风格采用课件第 35 页最基础的 **Target（直接列依赖）** 风格。

### 4.2 真实行为证据（本样本核心）

run-id `20260925-b14-e3`，源码基线 commit `baf5f829073251b5e01e8af6af1b89314f3116c3`：

| 步骤 | 命令 | 退出码 | 观察 |
| --- | --- | --- | --- |
| 初次完整构建 | `make` / `./app` | 0 / 0 | 输出 `1` |
| 仅改 `config.h` 为 2 | `make` | 0 | `make: 'app' is up to date.`（未重编译） |
| 同上 | `./app` | 0 | **仍输出 `1`** ← MD 的真实后果 |
| clean 对照 | `make clean && make` / `./app` | 0 / 0 | 输出 `2` |
| 应用参考补丁 | `git apply --check` / `git apply` | 0 / 0 | Makefile 与参考版哈希一致 |
| 修复后再改头文件为 3 | `make` / `./app` | 0 / 0 | 自动重编译，输出 `3` |
| 无效候选 | `make` | 2 | `cannot find does_not_exist.o`（应拒绝） |
| 恢复 | `make clean && make` / `./app` | 0 / 0 | 输出 `3` |
