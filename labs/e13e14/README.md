# 实验包接续方式

`scan_runtime_logs.py` 补足旧版 `secret_scan.py` 不扫描 `work/` 的范围缺口。将它复制到个人仓库的 `labs/e13e14/` 后调用。它只输出命中位置、类型和遮蔽后的值；退出码 0 为未命中，1 为命中，2 为路径缺失或没有可读文本。先在隔离测试副本用假 Key 验证，再检查本轮 E13/E14 证据目录。

E12 已完成 A/B 技术路线集成。E13–E14 复用 E11–E12 的 `run_e11e12.py`、`labs/e11e12`、数据请求和现有云机镜像。本目录不复制这些已实测的实现，避免向学生仓库覆盖代码。E13 的新测试应以个人分支加入原仓库；教师的 3 个未知项目或故障场景在开发阶段不公开，测试时发给学生运行。

测试阶段发放的三个项目在 `e13-upstream-student.zip`：jsmn、inih、tiny-AES-c 的固定上游源码及课程适配 Git 副本。包内有许可、来源和构建候选，不含教师判定清单；解压、生成请求和运行步骤见 `02_操作手册/03_E13三个项目运行指南.md`。

`handoff_a_to_b.py` 核对 A 的成功报告、目标提交及产物字节哈希，再生成 B 可消费的 `fixed-md` 信封，并保留 A 的 job_id、trace_id 和报告 SHA。B 的 `pipeline.py` 增加可选 `fixed_report_sha256`，在读取报告前校验传输后的字节。必须同时导入这两处修改，才可进行实时报告交接。命令见 E13 手册。

`compose.yaml`、`service.py` 和 `orchestrate.py` 为 E14 教师彩排的四容器入口。四个容器分别运行 BuildChecker、EChecker、DRAFT、MDFixer 的 HTTP 处理器；编排脚本经本机 18081–18084 端口调用，逐阶段写入新的 `work/` 证据目录。它们共享已构建的 E11/E12 教学镜像和课程工作目录；仅 DRAFT 挂载 Docker socket。运行前在服务器设置 `E14_ROOT`（个人仓库绝对路径）与 `E14_IMAGE`（本人已构建的固定镜像标签）。端口只绑定 `127.0.0.1`。

导入学生仓库时，将本目录的 Python 文件、`compose.yaml` 和 `tests/` 复制到仓库根目录的 `labs/e13e14/`；将 `.github/workflows/e13e14.yml` 复制到仓库根目录同名路径。工作流包含契约检查、Compose 配置、源码扫描、固定样例四容器构建与运行、日志扫描。它是待接入真实远端的 CI 模板；只有 Git 平台在目标提交上实际运行成功，才能填写 CI 通过。

本包还提供测试矩阵、命令路径和记录模板。扫描器的 C6 假 Key 命中、清理后复扫已在隔离云机测试副本通过；E13 的 A→B 当次报告交接、C4 超时与 C7 失败隔离也已在教师样例上通过。C5 沿用 E10 B 组错误补丁回滚样例作为前期回归。E14 的四容器教师样例五阶段已通过，完整结果见验证记录。跨组实际项目的 C1–C8 完整矩阵和 GitHub 门禁仍待学生执行；教师隐藏测试仍需在学生提交上进行。本包不把教学样例结果写成实际组项目通过。
